# REQ-001: Захват экрана с учётом мультимонитора, автокопирование в буфер и сохранение файлов

| Поле | Значение |
|---|---|
| Статус | Review |
| Приоритет | Must |
| Автор | Analyst |
| Дата | 2026-10-18 (ред. 2 — закрыты открытые вопросы); 2026-10-31 (ред. 3 — уточнён REQ-001.N6, CLR-006) |
| Связанные | US-001, US-002, US-003, US-004, US-005, US-006, US-007, RES-001 |

## 1. Контекст и цель

Пользователю Windows нужно быстро делать снимки экрана, в том числе на нескольких мониторах, и сразу пользоваться результатом:
вставлять его в мессенджер или документ (через буфер обмена) и находить потом на диске (через автосохранение в известную папку).
Встроенные средства (PrtSc, Win+Shift+S, Snipping Tool) требуют лишних действий: вручную сохранять файл, выбирать папку,
работать с монитором под курсором.

**Цель:** снимок делается одной горячей клавишей. После этого изображение уже лежит в буфере обмена и сохранено PNG-файлом
в директорию по умолчанию. Копию можно дополнительно сохранить в любую другую папку.

Решения, принятые с пользователем при уточнении (2026-10-18):

| Вопрос | Решение |
|---|---|
| Режимы захвата | Монитор под курсором, все мониторы одним изображением, произвольная область |
| Целевые ОС (v1) | Только Windows: Windows 10 и Windows 11 |
| Сценарий сохранения | Буфер всегда + автосохранение в директорию по умолчанию + отдельное действие «Сохранить как» |
| Запуск захвата | Глобальные горячие клавиши: `Ctrl+Shift+1` / `Ctrl+Shift+2` / `Ctrl+Shift+3` |
| Формат файла | Только PNG, в том числе в «Сохранить как» |
| Начальная директория по умолчанию | Системная папка «Снимки экрана» (`Pictures\Screenshots`) |
| Начальная папка «Сохранить как» | Последняя папка, выбранная в «Сохранить как» |
| Указатель мыши | Не попадает в снимок по умолчанию, включается настройкой |
| Пустые зоны виртуального стола | Заливаются серым цветом |
| Горячая клавиша «Сохранить как» | Не нужна |
| Уведомление | 3 секунды; имя снимка и папка, куда он сохранён |
| Режим «Область» | Только выделение прямоугольника, без модификаторов и правки выделения |
| Облачная история буфера (Win+V) | Снимки не исключаются |

## 2. Область охвата

- **Входит:**
  - три режима захвата: монитор под курсором, все мониторы, произвольная область (в том числе через границу мониторов);
  - корректная работа с любой раскладкой мониторов, разными разрешениями и разными коэффициентами масштабирования (HiDPI);
  - глобальные горячие клавиши для каждого режима;
  - автоматическое копирование снимка в системный буфер обмена;
  - автоматическое сохранение в PNG в директорию по умолчанию;
  - действие «Сохранить как» для последнего снимка;
  - настройка директории по умолчанию и её сохранение между запусками;
  - настройка «Включать указатель мыши в снимок»;
  - уведомление о результате захвата и об ошибках.
- **Не входит (v1):**
  - macOS, Linux (X11/Wayland);
  - захват отдельного окна, скроллинг-захват, запись видео/GIF;
  - аннотирование и редактирование снимка;
  - модификаторы выделения (Shift — квадрат, стрелки — подгонка) и правка выделения после отпускания кнопки;
  - форматы, отличные от PNG (JPEG, WebP);
  - горячая клавиша для «Сохранить как»;
  - исключение снимков из истории буфера обмена Windows;
  - история снимков (больше одного последнего), облачная загрузка, шаринг по ссылке;
  - захват с задержкой (таймер).

## 3. Функциональные требования

> Идентификаторы требований стабильны. Требования, добавленные во второй редакции, получили номера REQ-001.52 и далее
> и размещены в тематических разделах.

### 3.1. Запуск захвата

| ID | Требование | Приоритет |
|---|---|---|
| REQ-001.1 | Система должна предоставлять три режима захвата: «Монитор под курсором», «Все мониторы», «Область». | Must |
| REQ-001.2 | Система должна запускать каждый режим своей глобальной горячей клавишей. Клавиша должна срабатывать, когда приложение работает в фоне, свёрнуто или не имеет фокуса ввода. | Must |
| REQ-001.52 | Горячие клавиши по умолчанию: `Ctrl+Shift+1` — «Монитор под курсором», `Ctrl+Shift+2` — «Все мониторы», `Ctrl+Shift+3` — «Область». | Must |
| REQ-001.3 | Если горячую клавишу не удалось зарегистрировать (её уже занял другой процесс), система должна при запуске показать уведомление с названием конфликтующей комбинации. Остальные режимы должны продолжать работать. | Must |
| REQ-001.4 | Система должна позволять переназначить горячую клавишу каждого режима в настройках. Новое значение должно сохраняться между перезапусками. | Should |
| REQ-001.5 | Если захват или выделение области уже идёт, система должна игнорировать повторные нажатия горячих клавиш захвата. | Must |

### 3.2. Режим «Монитор под курсором»

| ID | Требование | Приоритет |
|---|---|---|
| REQ-001.6 | Система должна определять целевой монитор по положению курсора мыши в момент нажатия горячей клавиши. | Must |
| REQ-001.7 | Система должна захватывать всю площадь целевого монитора в его физическом разрешении. Размер изображения должен совпадать с разрешением монитора из параметров дисплея Windows (например, 3840×2160 при масштабе 150 %). | Must |
| REQ-001.8 | Если положение курсора нельзя однозначно отнести к одному монитору (курсор вне всех мониторов или ошибка API), система должна захватывать основной (primary) монитор. | Must |

### 3.3. Режим «Все мониторы»

| ID | Требование | Приоритет |
|---|---|---|
| REQ-001.9 | Система должна захватывать все подключённые активные мониторы в одно изображение. Его размер равен ограничивающему прямоугольнику виртуального рабочего стола в физических пикселях. | Must |
| REQ-001.10 | Система должна сохранять взаимное расположение мониторов на изображении таким, как оно задано в параметрах дисплея Windows, включая мониторы с отрицательными координатами (слева или выше основного) и портретную ориентацию. | Must |
| REQ-001.11 | Части ограничивающего прямоугольника, которые не покрыты ни одним монитором, система должна заполнять непрозрачным серым цветом `#808080` (RGB 128, 128, 128). Цвет не настраивается. | Should |
| REQ-001.12 | Если мониторы в режиме дублирования (клонирования), система должна включать дублированную область в изображение один раз. | Should |

### 3.4. Режим «Область»

| ID | Требование | Приоритет |
|---|---|---|
| REQ-001.13 | По горячей клавише режима «Область» система должна зафиксировать содержимое всех мониторов на момент нажатия («замороженный кадр») и показать поверх всех мониторов полноэкранный оверлей с этим кадром. | Must |
| REQ-001.14 | Система должна позволять выделить прямоугольную область перетаскиванием мыши с зажатой левой кнопкой. Выделение может пересекать границы мониторов. | Must |
| REQ-001.15 | Во время выделения система должна показывать размер выделенной области в физических пикселях (Ш×В). | Should |
| REQ-001.16 | Сразу после отпускания левой кнопки мыши система должна вырезать выделенную область из замороженного кадра и передать её дальше (в буфер и на сохранение). Подтверждение и правка выделения не требуются. | Must |
| REQ-001.17 | При нажатии Esc или правой кнопки мыши во время выделения система должна закрыть оверлей. Снимок не создаётся, буфер обмена и файлы не изменяются. | Must |
| REQ-001.18 | Если выделение меньше 2×2 физических пикселей (например, одиночный клик), система должна считать его отменой и действовать как в REQ-001.17. | Should |
| REQ-001.19 | Система должна вычислять выделенную область в физических пикселях без масштабирования, в том числе когда выделение пересекает мониторы с разными коэффициентами масштабирования. | Must |
| REQ-001.56 | Модификаторы выделения (Shift — квадрат, стрелки — подгонка по пикселю), перемещение и изменение размера выделения после отпускания кнопки. | Won't (v1) |

### 3.5. Общие требования к изображению

| ID | Требование | Приоритет |
|---|---|---|
| REQ-001.20 | Снимок должен совпадать с содержимым экрана пиксель в пиксель, без масштабирования и сглаживания, при любых коэффициентах масштабирования Windows от 100 % до 300 %, включая смешанные конфигурации. | Must |
| REQ-001.21 | Окна самого приложения (оверлей выделения, уведомления, окно настроек) не должны попадать в снимок. | Must |
| REQ-001.22 | По умолчанию указатель мыши не должен попадать в снимок. | Must |
| REQ-001.53 | Система должна предоставлять в настройках флажок «Включать указатель мыши в снимок» (по умолчанию выключен). Если флажок включён, система должна рисовать на снимке текущий системный указатель (с его формой) в той позиции, где он находился в момент нажатия горячей клавиши. В режиме «Область» указатель попадает в снимок, только если эта позиция внутри выделенной области; перекрестие оверлея в снимок не попадает. Значение сохраняется между перезапусками. | Should |

### 3.6. Буфер обмена

| ID | Требование | Приоритет |
|---|---|---|
| REQ-001.23 | После каждого успешного захвата система должна автоматически помещать изображение в системный буфер обмена Windows в формате, который можно вставить как изображение в Paint, Microsoft Word, Telegram Desktop и браузер (Chrome/Edge). | Must |
| REQ-001.24 | Копирование в буфер должно выполняться независимо от результата сохранения файла: ошибка сохранения не должна мешать копированию, и наоборот. | Must |
| REQ-001.25 | Если буфер обмена временно занят другим процессом, система должна повторить попытку (не менее 5 попыток в течение не более 1 с). После неудачи последней попытки система должна показать уведомление «Не удалось скопировать в буфер обмена»; файл при этом сохраняется. | Must |
| REQ-001.26 | Изображение должно оставаться в буфере обмена после завершения работы приложения. | Should |
| REQ-001.58 | Исключение снимков из истории буфера обмена Windows (Win+V) и из облачной синхронизации буфера. Снимки ведут себя как обычное содержимое буфера. | Won't (v1) |

### 3.7. Автосохранение в директорию по умолчанию

| ID | Требование | Приоритет |
|---|---|---|
| REQ-001.27 | После каждого успешного захвата система должна автоматически сохранять снимок в формате PNG в директорию по умолчанию. | Must |
| REQ-001.28 | Система должна давать файлу имя по шаблону `Screenshot_yyyy-MM-dd_HH-mm-ss.png`, где время — локальное время момента захвата. | Must |
| REQ-001.29 | Если файл с таким именем уже существует, система должна добавить к имени суффикс `_1`, `_2`, … (`Screenshot_2026-10-18_20-00-48_1.png`). Существующие файлы не должны перезаписываться. | Must |
| REQ-001.30 | Если директории по умолчанию не существует, система должна создать её вместе с промежуточными директориями. | Must |
| REQ-001.31 | Если записать файл невозможно (нет прав, диск заполнен или отключён, путь недоступен), система должна показать уведомление с причиной и предложить «Сохранить как». Снимок должен оставаться в буфере обмена и в памяти как последний снимок. | Must |
| REQ-001.32 | Запись файла должна быть атомарной: при сбое во время записи в директории не должен оставаться повреждённый или неполный PNG-файл с итоговым именем. | Should |
| REQ-001.33 | Сохранение файла должно выполняться асинхронно и не блокировать следующий захват. | Must |
| REQ-001.34 | После успешного захвата система должна показать уведомление с именем сохранённого файла (например, `Screenshot_2026-10-18_20-00-48.png`) и полным путём к папке, куда он сохранён (например, `C:\Users\Александр\Pictures\Screenshots`). Клик по уведомлению открывает папку с файлом, и файл в ней выделен. | Must |
| REQ-001.54 | Уведомления приложения (об успехе и об ошибках) должны автоматически скрываться через 3 секунды после появления. Новое уведомление заменяет предыдущее, а не накладывается на него. | Must |
| REQ-001.35 | Система должна позволять отключить автосохранение в настройках, чтобы снимок попадал только в буфер обмена. | Could |

### 3.8. «Сохранить как»

| ID | Требование | Приоритет |
|---|---|---|
| REQ-001.36 | Система должна хранить в памяти последний успешный снимок до следующего захвата или до выхода из приложения. | Must |
| REQ-001.37 | Система должна предоставлять действие «Сохранить как…» для последнего снимка: из уведомления о захвате (пока оно видно) и из меню значка в системном трее (всегда, пока есть последний снимок). | Must |
| REQ-001.38 | Действие «Сохранить как…» должно открывать стандартный диалог сохранения файла Windows с предзаполненным именем по шаблону REQ-001.28 и фильтром `PNG (*.png)`. Начальная папка диалога — последняя папка, в которую пользователь сохранял через «Сохранить как…». Если такой папки ещё нет или она недоступна — директория по умолчанию. | Must |
| REQ-001.55 | Система должна запоминать последнюю папку «Сохранить как…» между перезапусками приложения. Эта папка хранится отдельно от директории по умолчанию. | Should |
| REQ-001.39 | Файл всегда сохраняется в формате PNG. Если имя, введённое пользователем, не заканчивается на `.png` (без учёта регистра), система должна дописать `.png`: `login-error` → `login-error.png`, `login.jpg` → `login.jpg.png`, `v1.2` → `v1.2.png`. | Must |
| REQ-001.40 | Если выбранный файл уже существует, система должна запросить подтверждение перезаписи. | Must |
| REQ-001.41 | Действие «Сохранить как…» должно сохранять копию снимка и не должно изменять директорию по умолчанию и ранее автосохранённый файл. | Must |
| REQ-001.42 | Если снимка ещё нет (в текущем сеансе не было ни одного захвата), пункт «Сохранить как…» должен быть недоступен. | Must |
| REQ-001.57 | Глобальная горячая клавиша для «Сохранить как…». | Won't (v1) |

| REQ-001.47 | Если сохранённая директория недоступна при запуске (например, отключён съёмный или сетевой диск), система не должна молча менять настройку. Ошибка обрабатывается при сохранении по REQ-001.31. | Should |

| REQ-001.49 | Система должна корректно работать с путями, содержащими не-ASCII символы (кириллица) и пробелы. | Must |

## 4. Нефункциональные требования

Эталонные конфигурации для измерений (**Допущение**): Windows 11 23H2 x64 и Windows 10 22H2 x64, CPU уровня Intel Core i5
10-го поколения, 16 ГБ RAM, SSD, до трёх мониторов 3840×2160. Время измеряется от события горячей клавиши, перцентиль p95
по 50 замерам, на «прогретой» JVM. Требования N1–N5 должны выполняться на обеих ОС.

| ID | Категория | Требование (измеримое) |
|---|---|---|
| REQ-001.N1 | Производительность | «Монитор под курсором» 3840×2160: от нажатия клавиши до появления изображения в буфере обмена ≤ 300 мс. |
| REQ-001.N2 | Производительность | «Все мониторы», 3 × 3840×2160: от нажатия клавиши до появления изображения в буфере обмена ≤ 700 мс. |
| REQ-001.N3 | Производительность | «Область»: оверлей с замороженным кадром появляется на всех мониторах ≤ 250 мс после нажатия клавиши. |
| REQ-001.N4 | Производительность | Файл PNG 3840×2160 полностью записан на SSD ≤ 1,5 с после захвата. Запись идёт в фоне (REQ-001.33). |

## 5. Платформы и окружение

| Платформа | Поддержка в v1 | Оговорки |
|---|---|---|
| Windows 10 22H2 (x64) | Да | Обязательная платформа v1 |
| Windows 11 22H2+ (x64) | Да | Обязательная платформа v1 |
| Windows ARM64 | Нет | Кандидат на последующие версии |
| macOS | Нет (Won't в v1) | Понадобится разрешение Screen Recording; отдельный анализ |
| Linux X11 | Нет (Won't в v1) | — |
| Linux Wayland | Нет (Won't в v1) | Понадобится `xdg-desktop-portal`; отдельный анализ |

**Мультимонитор:** любое количество мониторов (тестирование — до 4), произвольная раскладка, отрицательные координаты,
разные разрешения, портретная ориентация, «горячее» подключение и отключение.

**HiDPI:** масштабы 100–300 %, смешанные коэффициенты на разных мониторах. Захват всегда в физических пикселях.

**Не поддерживается (ограничения ОС):** защищённый рабочий стол (UAC, Ctrl+Alt+Del, экран блокировки) и DRM-защищённый
контент (часть видеоплееров и стриминговых сервисов). Для такого контента допустим чёрный прямоугольник на снимке.

**HDR:** при включённом HDR цвета на снимке могут отличаться от видимых (см. RES-001). В v1 это фиксируется как известное ограничение.

## 6. Сценарии и граничные случаи

**Основные сценарии:**
1. `Ctrl+Shift+1` → снимок монитора под курсором в буфере → файл сохранён → уведомление на 3 с с именем файла и папкой.
2. `Ctrl+Shift+2` → одно изображение всего виртуального рабочего стола (пустые зоны серые) → буфер + файл + уведомление.
3. `Ctrl+Shift+3` → оверлей с замороженным кадром → выделение → отпускание кнопки → буфер + файл + уведомление.
4. Пользователь выбирает «Сохранить как…» из уведомления или трея → диалог открывается в последней папке «Сохранить как» → копия сохранена.
5. Пользователь меняет директорию по умолчанию в настройках → следующие снимки сохраняются туда.
6. Пользователь включает «Включать указатель мыши в снимок» → на следующих снимках виден указатель.

**Граничные случаи:**
- Курсор точно на границе двух мониторов: выбирается монитор, которому принадлежит точка по правилу Windows `MonitorFromPoint(MONITOR_DEFAULTTOPRIMARY)`.
- Мониторы с разным масштабом (например, ноутбук 150 % + внешний 100 %): нет разрывов, наложений и масштабирования на склейке.
- Мониторы разной высоты или со смещением: пустые зоны заливаются серым по REQ-001.11.
- Монитор отключили между нажатием клавиши и захватом: захват не падает. Либо захватывается актуальная конфигурация, либо показывается ошибка без сбоя приложения.
- Изменение раскладки или масштаба во время работы приложения (REQ-001.N11).
- Выделение области начато на одном мониторе и закончено на другом, в том числе «вверх-влево» (обратное направление).
- Выделение вышло за пределы мониторов в пустую зону виртуального стола: эта часть заливается серым по REQ-001.11.
- Очень быстрые повторные нажатия клавиши (REQ-001.5) и захваты в одну и ту же секунду (суффикс имени, REQ-001.29).
- Несколько захватов подряд: каждое новое уведомление заменяет предыдущее (REQ-001.54).
- Пользователь не успел нажать «Сохранить как…» за 3 с — действие доступно в меню трея (REQ-001.37).
- Буфер обмена заблокирован другим приложением (менеджер буфера, RDP) — REQ-001.25.
- Директория по умолчанию удалена, переименована, на отключённом USB или сетевом диске, без прав записи, диск заполнен — REQ-001.31.
- Последняя папка «Сохранить как» удалена или на отключённом диске — диалог открывается в директории по умолчанию (REQ-001.38).
- Профиль пользователя с кириллицей в пути (`C:\Users\Александр\Pictures\Screenshots`) — REQ-001.49.
- Папка «Изображения» перенаправлена в OneDrive — REQ-001.44.
- Горячая клавиша занята другим приложением или системой — REQ-001.3. `Ctrl+Shift+1/2/3` перехватываются глобально: в приложениях, где эти сочетания заняты (например, в Microsoft Excel это форматы числа, времени и даты), они перестанут работать, пока запущено приложение. Решение — переназначение по REQ-001.4.
- Включён флажок указателя, а в режиме «Область» указатель в момент нажатия находился вне будущего выделения — указатель на снимок не попадает (REQ-001.53). В режиме «Все мониторы» указатель попадает всегда, в режиме «Монитор под курсором» — тоже (он по определению на этом мониторе).
- Открыт полноэкранный exclusive-mode контент (игра) — возможен чёрный снимок (см. RES-001).
- Сеанс RDP: работает в пределах удалённого рабочего стола. **Допущение:** официально в v1 не тестируется.
- Очень большой виртуальный рабочий стол (например, 3 × 4K = 11520×2160 ≈ 99,5 МБ в ARGB) — REQ-001.N6.

## 7. Допущения и ограничения

- **Допущение:** приложение — десктопное JVM-приложение на Kotlin, работает в фоне и имеет значок в системном трее (через него доступны «Сохранить как…», «Настройки», «Выход»). UI-фреймворк не выбран — нужен ADR.
- **Допущение:** в памяти хранится только один последний снимок (без истории).
- **Допущение:** режим «Область» работает по схеме «замороженного кадра», а не «живого» экрана. Так в снимок попадают всплывающие меню и подсказки, и он не зависит от изменений экрана во время выделения.
- **Допущение:** настройки хранятся локально в профиле пользователя. Это директория по умолчанию, последняя папка «Сохранить как», горячие клавиши и флажок указателя. Механизм хранения (файл в `%APPDATA%` или `java.util.prefs`) выбирается отдельным ADR.
- **Допущение:** серый цвет заливки — средний серый `#808080`. Значение уточняется при приёмке, если нужен другой оттенок.
- **Допущение:** уведомление — собственное всплывающее окно приложения (в правом нижнем углу основного монитора), а не системный toast Windows. Windows сама управляет длительностью показа toast-уведомлений (по системным настройкам специальных возможностей, обычно ≥ 5 с), поэтому с ними нельзя выполнить требование «3 секунды» (REQ-001.54). Подробнее в RES-001.
- **Ограничение:** AWT не умеет регистрировать глобальные горячие клавиши. Нужен нативный механизм (см. RES-001).
- **Ограничение:** при копировании в буфер обмена прозрачность не сохраняется. Поэтому для REQ-001.11 используется непрозрачная заливка.
- **Ограничение:** если у пользователя включены история буфера (Win+V) или синхронизация буфера между устройствами, снимки попадают туда так же, как любое другое содержимое буфера (REQ-001.58).
