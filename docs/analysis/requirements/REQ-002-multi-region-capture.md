# REQ-002: Режим «Несколько областей» — выделение нескольких регионов и склейка в одно изображение

| Поле | Значение |
|---|---|
| Статус | Draft |
| Приоритет | Should |
| Автор | Analyst |
| Дата | 2026-11-08 |
| Связанные | REQ-001, US-008, US-009, US-010 |

## 1. Контекст и цель

Пользователю часто нужно показать в одном снимке несколько разнесённых по экрану фрагментов (например, поле формы
слева и сообщение об ошибке справа внизу), без лишнего содержимого между ними. Сейчас для этого надо сделать
несколько снимков режимом «Область» (REQ-001, `Ctrl+Shift+3`) и склеить их вручную в редакторе.

**Цель:** новый режим захвата «Несколько областей». По горячей клавише пользователь выделяет на замороженном кадре
до N непересекающихся прямоугольников, подтверждает выбор клавишей, и система собирает **только содержимое этих
прямоугольников** в одно изображение. Взаимное расположение фрагментов сохраняется, а пустое пространство между ними
«схлопывается». Оставшиеся пустоты заливаются однотонным цветом. Результат обрабатывается так же, как любой снимок
REQ-001: буфер обмена, автосохранение, уведомление, «Сохранить как…».

Решения, принятые с пользователем при уточнении (2026-11-08):

| Вопрос | Решение |
|---|---|
| Горячая клавиша по умолчанию | `Ctrl+Shift+4` (настраивается) |
| Лимит регионов | По умолчанию 10, настраивается |
| Подтверждение | `Enter` (настраивается) |
| Алгоритм склейки | Сжатие пустот: удаляются пустые полосы по X и по Y, взаимное расположение сохраняется |
| Отступ между регионами | Нет, вплотную |
| Цвет заливки пустот | Настраиваемый, по умолчанию `#808080` |
| Правка до подтверждения | Только удаление: последнего региона (клавишей) и любого региона (правой кнопкой по нему). Перемещения и изменения размера нет |
| Пересекающийся регион / превышение лимита | Регион не добавляется, на оверлее — подсказка |
| Настраиваемость клавиш | Все клавиши и сочетания режима настраиваются |

## 2. Область охвата

- **Входит:**
  - новый режим захвата «Несколько областей» с собственной глобальной горячей клавишей;
  - выделение от 1 до N прямоугольных регионов на замороженном кадре, в том числе через границы мониторов;
  - запрет пересечения регионов, лимит количества;
  - удаление последнего региона и удаление произвольного региона;
  - подтверждение и отмена;
  - склейка регионов в одно изображение по алгоритму «сжатие пустот» с заливкой цветом;
  - настройки: горячая клавиша, клавиши оверлея, лимит регионов, цвет заливки;
  - передача результата в общий конвейер REQ-001 (буфер, автосохранение, уведомление, «Сохранить как…»).
- **Не входит:**
  - перемещение и изменение размера уже выделенных регионов, модификаторы выделения (аналогично REQ-001.56);
  - непрямоугольные регионы, выделение окна по клику;
  - ручная перестановка порядка регионов, альтернативные раскладки (строки, сетка, по порядку выделения);
  - отступы, рамки, тени, подписи и номера регионов на итоговом изображении;
  - прозрачный фон (ограничение буфера обмена, см. REQ-001 §7);
  - сохранение каждого региона отдельным файлом.

## 3. Функциональные требования

### 3.1. Запуск режима

| ID | Требование | Приоритет |
|---|---|---|
| REQ-002.1 | Система должна предоставлять режим захвата «Несколько областей», запускаемый глобальной горячей клавишей по правилам REQ-001.2, REQ-001.3, REQ-001.5. | Must |
| REQ-002.2 | Горячая клавиша по умолчанию — `Ctrl+Shift+4`. Система должна позволять переназначить её в настройках (по правилам REQ-001.4); значение сохраняется между перезапусками. | Must |
| REQ-002.3 | По горячей клавише система должна зафиксировать замороженный кадр всех мониторов и показать оверлей так же, как в режиме «Область» (REQ-001.13). Все последующие регионы вырезаются из этого одного кадра. | Must |

### 3.2. Выделение регионов

| ID | Требование | Приоритет |
|---|---|---|
| REQ-002.4 | Система должна позволять выделять регион перетаскиванием с зажатой левой кнопкой мыши (как REQ-001.14). После отпускания кнопки оверлей **не закрывается**: регион добавляется в набор и остаётся видимым, можно выделять следующий. | Must |
| REQ-002.5 | Выделенные регионы должны оставаться визуально отмеченными на оверлее (рамка, незатемнённое содержимое) и пронумерованными в порядке добавления. Номера и рамки в итоговое изображение не попадают. | Must |
| REQ-002.6 | Во время выделения система должна показывать размер текущего региона в физических пикселях (как REQ-001.15) и счётчик «k / N» (выделено / лимит). | Should |
| REQ-002.7 | Регионы не должны пересекаться: никакой физический пиксель не может принадлежать двум регионам. Касание по границе (общая сторона без общих пикселей) допускается. | Must |
| REQ-002.8 | Если отпущенное выделение пересекается хотя бы с одним существующим регионом, система должна не добавлять его и показать на оверлее подсказку «Области не должны пересекаться» (≈ 2 с). Существующие регионы не изменяются. Во время перетаскивания пересечение должно подсвечиваться (например, красной рамкой). | Must |
| REQ-002.9 | Начало перетаскивания внутри существующего региона не создаёт новый регион (это пересечение по REQ-002.8). | Must |
| REQ-002.10 | Выделение меньше 2×2 физических пикселей игнорируется (не добавляется, оверлей остаётся открытым). Это отличается от REQ-001.18, где такой клик отменяет захват. | Must |
| REQ-002.11 | Система должна ограничивать количество регионов значением настройки «Максимум областей» (по умолчанию 10). Когда лимит достигнут, новое выделение не начинается, и система показывает подсказку «Достигнут лимит: N областей. Enter — собрать снимок». | Must |
| REQ-002.12 | Вычисление координат регионов — в физических пикселях без масштабирования, в том числе через мониторы с разным масштабом (как REQ-001.19). Часть региона вне мониторов заливается цветом REQ-001.11 (`#808080`, как в режиме «Область»), а не цветом заливки пустот REQ-002.21. | Must |

### 3.3. Правка, подтверждение, отмена

| ID | Требование | Приоритет |
|---|---|---|
| REQ-002.13 | Клавиша «Удалить последнюю область» (по умолчанию `Backspace`, дополнительно `Ctrl+Z`) удаляет последний добавленный регион. Если регионов нет — ничего не происходит. | Must |
| REQ-002.14 | Щелчок правой кнопкой мыши внутри существующего региона удаляет этот регион. Номера остальных регионов перенумеровываются по порядку. | Should |
| REQ-002.15 | Щелчок правой кнопкой вне регионов ничего не делает (в отличие от REQ-001.17, чтобы случайно не потерять набор). | Must |
| REQ-002.16 | Клавиша «Собрать снимок» (по умолчанию `Enter`, дополнительно `NumPad Enter`) закрывает оверлей и запускает склейку по разделу 3.4. | Must |
| REQ-002.17 | Если при нажатии «Собрать снимок» нет ни одного региона, оверлей не закрывается, система показывает подсказку «Выделите хотя бы одну область». | Must |
| REQ-002.18 | Клавиша «Отмена» (по умолчанию `Esc`) закрывает оверлей без создания снимка: буфер обмена, файлы и последний снимок не меняются. | Must |
| REQ-002.19 | На оверлее должна быть ненавязчивая подсказка с текущими назначенными клавишами (например, «Enter — собрать · Backspace — удалить последнюю · Esc — отмена»). | Should |

### 3.4. Склейка

| ID | Требование | Приоритет |
|---|---|---|
| REQ-002.20 | Система должна собирать итоговое изображение только из содержимого регионов по алгоритму «сжатие пустот»: (1) берётся ограничивающий прямоугольник всех регионов; (2) удаляются все вертикальные полосы (столбцы пикселей), не пересекающие ни один регион; (3) удаляются все горизонтальные полосы (строки), не пересекающие ни один регион; (4) каждый регион переносится без масштабирования, его новая позиция — исходная минус ширина/высота удалённых полос левее/выше него. | Must |
| REQ-002.21 | Пиксели итогового изображения, не принадлежащие ни одному региону, система должна заливать непрозрачным цветом из настройки «Цвет заливки» (по умолчанию `#808080`). | Must |
| REQ-002.22 | Склейка должна сохранять взаимный порядок: если регион A целиком левее (выше) региона B на экране, он остаётся левее (выше) и на изображении. Регионы на результате не пересекаются, не масштабируются, отступов между ними нет. | Must |
| REQ-002.23 | Результат не зависит от порядка выделения регионов, только от их положения. | Must |
| REQ-002.24 | При одном регионе результат идентичен снимку режима «Область» с тем же прямоугольником. | Must |
| REQ-002.25 | Итоговое изображение обрабатывается конвейером REQ-001: буфер (REQ-001.23–26), автосохранение и имя файла (REQ-001.27–35), уведомление (REQ-001.34, 54), «Сохранить как…» (REQ-001.36–42). | Must |
| REQ-002.26 | Указатель мыши (если включён REQ-001.53) рисуется, только если его позиция в момент нажатия горячей клавиши попала внутрь одного из регионов; рисуется в соответствующей перенесённой позиции. | Could |

Иллюстрация (физические пиксели). Регионы A = (0,0)–(100,50), B = (500,300)–(700,400):
столбцы 100–500 и строки 50–300 пусты и удаляются. Результат 300×150: A в (0,0) размером 100×50,
B в (100,50) размером 200×100; остальное — цвет заливки.

```
Экран:                         Результат:
A▇▇                            A▇▇░░░░
                               ░░░B▇▇▇
            B▇▇▇▇              ░░░B▇▇▇
            B▇▇▇▇
```

## 6. Сценарии и граничные случаи

**Основной сценарий:** `Ctrl+Shift+4` → оверлей → выделить 3 региона → `Enter` → склеенный снимок в буфере, файл
`Screenshot_…png` сохранён, уведомление.

**Граничные случаи:**
- Регионы на разных мониторах с разным масштабом — склейка в физических пикселях без масштабирования.
- Регионы касаются по стороне — допустимо (REQ-002.7), на результате остаются вплотную.
- Регионы «по диагонали» (проекции не перекрываются ни по X, ни по Y) — результат «лесенкой», остальное — заливка.
- Регионы в одну строку разной высоты — выравниваются по исходной вертикальной позиции, пустоты сверху/снизу — заливка.
- Регион, проекция которого перекрывает проекции нескольких других, — пустые полосы удаляются, только если не пересекают **ни один** регион; итоговые пустоты внутри — заливка.
- Перетаскивание началось вне регионов, а закончилось внутри другого — пересечение, отклоняется (REQ-002.8).
- Лимит достигнут, затем регион удалён — выделение снова доступно.
- Повторное нажатие `Ctrl+Shift+4` или других горячих клавиш захвата при открытом оверлее — игнорируется (REQ-001.5).
- Отключение монитора при открытом оверлее — **Допущение:** работа продолжается с замороженным кадром; поведение как в REQ-001.
- Пользователь задал цвет заливки, совпадающий с содержимым регионов — допустимо, границы не рисуются.
- Пользователь назначил `Enter` на «Отмену» и `Esc` на «Собрать» — допустимо, если нет конфликтов (REQ-002.29).
- Назначение клавиши оверлея, совпадающей с глобальной горячей клавишей другого режима, — **Допущение:** допустимо, при открытом оверлее приоритет у действия оверлея.

## 7. Допущения и ограничения

- **Допущение:** оверлей и замороженный кадр переиспользуются из режима «Область» (REQ-001.13); отличается только логика завершения выделения.
- **Допущение:** «прижимание» понимается как удаление пустых полос целиком (REQ-002.20). Это не плотная упаковка: внутри результата могут оставаться пустоты, если регионы расположены «по диагонали». Пользователь подтвердил этот вариант.
- **Допущение:** допустимый диапазон лимита 2–50 выбран аналитиком, чтобы ограничить нагрузку на UI и память.
- **Допущение:** части регионов вне мониторов заливаются `#808080` (REQ-001.11), а не цветом заливки режима — чтобы содержимое региона совпадало с режимом «Область».
- **Ограничение:** прозрачность фона невозможна (буфер обмена CF_DIB, REQ-001 §7).

## 8. Открытые вопросы

Закрытые (ответы пользователя от 2026-11-08): алгоритм склейки, правка регионов, пересечения и лимит, цвет заливки, отступы — см. таблицу §1.

Некритичные (приняты значения по умолчанию):

- [ ] «Все клавиши должны настраиваться» — распространять ли настройку клавиш оверлея (`Esc`) на существующий режим «Область» REQ-001? Сейчас не входит в REQ-002.
- [ ] Части регионов вне мониторов: `#808080` или цвет заливки режима (REQ-002.12).
- [ ] Диапазон лимита 2–50.
- [ ] Правый клик вне регионов — ничего (REQ-002.15) или отмена, как в REQ-001.17.
