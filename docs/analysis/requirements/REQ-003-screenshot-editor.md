# REQ-003: Редактор снимков — рисование карандашом, перемещение и склейка областей

| Поле | Значение |
|---|---|
| Статус | Draft |
| Приоритет | Should |
| Автор | Analyst |
| Дата | 2026-11-08 |
| Связанные | REQ-001, REQ-002, US-011, US-012, US-013, US-014, ADR-005 |

## 1. Контекст и цель

Сейчас снимок сразу после захвата попадает в буфер обмена и на диск (REQ-001.23, REQ-001.27). Пометить что-то на
снимке или поправить раскладку фрагментов режима «Несколько областей» (REQ-002) можно только во внешнем редакторе.

**Цель:** добавить встроенный редактор снимков, который включается настройкой. Если редактор выключен, всё работает
как сейчас. Если включён, снимок сначала открывается в редакторе, а в буфер и на диск попадает только после
действия пользователя. Первая версия редактора умеет:

- рисовать карандашом по снимку (цвет, толщина, отмена и повтор);
- для режима «Несколько областей» — перемещать фрагменты и заново склеивать их.

Решения, принятые с пользователем при уточнении (2026-11-08):

| Вопрос | Решение |
|---|---|
| Включение | Флажок в настройках, по умолчанию выключен |
| Буфер и автосохранение при включённом редакторе | Только после действия в редакторе. До этого буфер, файлы и последний снимок не меняются |
| Действия завершения | «Готово» (буфер + автосохранение), «Копировать» (только буфер), «Сохранить как…», «Отмена» (`Esc`) |
| Карандаш | Выбор цвета и толщины, отмена (Undo) и повтор (Redo) |
| Области в редакторе | Открываются уже склеенными (REQ-002.20), каждую можно перетащить. Кнопка «Склеить» снова сжимает пустоты |
| Наложение областей | Запрещено (как REQ-002.7) |
| Перемещение и рисование | Перемещать можно, пока на снимке нет штрихов. Если отменить все штрихи, перемещение снова доступно |
| Переключение действий мыши | Явные инструменты «Перемещение» и «Карандаш» |
| Окно | Обычное окно, развёрнутое на мониторе под курсором. Снимок вписывается в окно, масштаб можно менять |
| Горячая клавиша захвата при открытом редакторе | Игнорируется |

## 2. Область охвата

- **Входит:**
  - настройка «Открывать снимок в редакторе»;
  - окно редактора для снимков всех режимов (REQ-001.1, REQ-002.1);
  - масштаб просмотра (вписать в окно, 100 %, Ctrl + колесо) и прокрутка;
  - инструмент «Карандаш»: выбор цвета и толщины, запоминание выбора;
  - отмена и повтор действий (Undo / Redo);
  - инструмент «Перемещение» и действие «Склеить» для снимков режима «Несколько областей»;
  - действия «Готово», «Копировать», «Сохранить как…», «Отмена»;
  - встраивание редактора в общий конвейер REQ-001 (буфер, автосохранение, уведомление, последний снимок).
- **Не входит (в этой версии):**
  - другие инструменты: стрелки, прямоугольники, текст, маркер, размытие, обрезка, ластик;
  - изменение размера, поворот, удаление и дублирование фрагментов; добавление новых областей из редактора;
  - перемещение фрагментов в режимах, отличных от «Несколько областей»;
  - перемещение фрагментов после появления штрихов (штрихи не привязаны к фрагментам);
  - открытие в редакторе произвольных файлов с диска и повторное открытие уже сохранённого снимка;
  - несколько окон редактора одновременно;
  - настройка клавиш редактора (в этой версии клавиши фиксированы);
  - форматы, отличные от PNG.

### 3.4. Перемещение и склейка областей (режим «Несколько областей»)

| ID | Требование | Приоритет |
|---|---|---|
| REQ-003.23 | Для снимка режима «Несколько областей» редактор должен открываться с раскладкой, рассчитанной по REQ-002.20. Каждая область — отдельный фрагмент, пустоты залиты цветом REQ-002.21. Инструмент по умолчанию — «Перемещение». | Must |
| REQ-003.24 | Инструментом «Перемещение» пользователь перетаскивает фрагмент левой кнопкой мыши. Фрагмент сдвигается на целое число физических пикселей и не масштабируется. При наведении на фрагмент курсор меняется на «перемещение», а фрагмент подсвечивается рамкой. Рамки и подсветка в итоговое изображение не попадают. | Must |
| REQ-003.25 | Фрагменты не должны пересекаться: никакой пиксель не может принадлежать двум фрагментам. Касание по стороне допускается. Если во время перетаскивания фрагмент пересекается с другим, система подсвечивает это (например, красной рамкой). Если отпустить кнопку в положении с пересечением, фрагмент возвращается туда, откуда его начали тащить, и показывается подсказка «Области не должны пересекаться». | Must |
| REQ-003.26 | Итоговое изображение — ограничивающий прямоугольник всех фрагментов. Его левый верхний угол всегда (0, 0): холст сдвигается после каждого перемещения. Пиксели вне фрагментов заливаются цветом REQ-002.21. Размер Ш×В в окне обновляется сразу. | Must |
| REQ-003.27 | Фрагмент можно перетащить за текущие границы изображения: изображение расширяется. Система ограничивает перемещение так, чтобы ширина изображения не превышала сумму ширин всех фрагментов, а высота — сумму их высот. | Must |
| REQ-003.28 | Действие «Склеить» применяет алгоритм REQ-002.20 к текущим позициям фрагментов: удаляет пустые полосы по X и по Y и сохраняет взаимное расположение фрагментов. Если пустых полос нет, раскладка не меняется. | Must |
| REQ-003.29 | Фрагменты можно двигать стрелками клавиатуры: выбранный (последний перемещённый или кликнутый) фрагмент сдвигается на 1 px, с `Shift` — на 10 px. Ограничения REQ-003.25 и REQ-003.27 действуют: сдвиг, приводящий к пересечению, не выполняется. | Could |
| REQ-003.30 | Перемещать фрагменты и выполнять «Склеить» можно только пока на изображении нет штрихов карандаша. Когда есть хотя бы один штрих (с учётом Undo), инструмент «Перемещение» и «Склеить» недоступны. Подсказка: «Перемещение недоступно после рисования. Отмените штрихи, чтобы двигать области». | Must |
| REQ-003.31 | Указатель мыши, нарисованный на фрагменте (REQ-002.26), перемещается вместе с фрагментом. | Could |
| REQ-003.32 | При одной области перемещение доступно, но не меняет итоговое изображение (ограничивающий прямоугольник одного фрагмента — сам фрагмент). | Should |

### 3.5. История изменений

| ID | Требование | Приоритет |
|---|---|---|
| REQ-003.33 | Система должна вести общую историю изменений: штрих карандаша, перемещение фрагмента (одно перетаскивание или одно нажатие стрелки — одно изменение), «Склеить». | Must |
| REQ-003.34 | «Отменить» (`Ctrl+Z`, кнопка) отменяет последнее изменение. «Повторить» (`Ctrl+Y` и `Ctrl+Shift+Z`, кнопка) возвращает последнее отменённое. Новое изменение после отмены очищает список повтора. Кнопки недоступны, когда отменять или повторять нечего. | Must |
| REQ-003.35 | Глубина истории — не менее 100 изменений в рамках одного открытия редактора. | Should |
| REQ-003.36 | После отмены всех изменений изображение должно совпадать с исходным снимком пиксель в пиксель. | Must |

### 3.6. Завершение редактирования

| ID | Требование | Приоритет |
|---|---|---|

| REQ-003.39 | «Сохранить как…» (кнопка, `Ctrl+Shift+S`) открывает диалог по правилам REQ-001.38–41 и REQ-001.55 и сохраняет текущее итоговое изображение. Последний снимок обновляется. Буфер и директория по умолчанию не меняются. Редактор остаётся открытым. | Should |

Изменения будут потеряны.» с вариантами «Закрыть» и «Вернуться». | Must |
| REQ-003.41 | При «Отмене» буфер обмена, файлы и последний снимок не меняются, кроме результатов уже выполненных «Копировать» и «Сохранить как…». | Must |
| REQ-003.42 | Имя автосохраняемого файла (REQ-001.28) строится по времени захвата, а не по времени нажатия «Готово». | Must |
| REQ-003.43 | «Готово» без изменений даёт изображение, идентичное снимку, который был бы получен при выключенном редакторе. | Must |
| REQ-003.44 | Если запись в буфер или на диск по «Готово» завершилась ошибкой, применяется обработка REQ-001.25 и REQ-001.31. Отредактированное изображение остаётся последним снимком и доступно для «Сохранить как…» из трея. | Must |
| REQ-003.45 | При выходе из приложения через трей с открытым редактором действует правило REQ-003.40: если есть несохранённые изменения, система спрашивает подтверждение. | Should |

## 5. Платформы и окружение

Как REQ-001 §5: Windows 10 22H2 и Windows 11 x64. macOS и Linux — Won't.

**HiDPI:** окно редактора может открыться на мониторе с любым масштабом (100–300 %). При масштабе просмотра 100 % один
пиксель снимка равен одному физическому пикселю экрана, а не логическому (DIP). **Допущение:** «100 %» означает
1:1 в физических пикселях, поэтому на мониторе 200 % снимок выглядит как на исходном экране, а не вдвое больше.

**Мультимонитор:** окно открывается на мониторе под курсором (REQ-003.7), пользователь может перенести его на другой
монитор. Масштаб просмотра при этом не меняется.

## 6. Сценарии и граничные случаи

**Основные сценарии:**

1. Редактор выключен: `Ctrl+Shift+3` → область → буфер + файл + уведомление (без изменений по сравнению с REQ-001).
2. Редактор включён: `Ctrl+Shift+3` → область → редактор → пользователь обводит кнопку красным карандашом → `Ctrl+Enter`
   → изображение со штрихом в буфере, файл `Screenshot_…png` сохранён, уведомление.
3. Редактор включён: `Ctrl+Shift+4` → три области → `Enter` → редактор со склеенными фрагментами → пользователь
   перетаскивает фрагмент B под фрагмент A → «Склеить» → переключается на «Карандаш» → подчёркивает текст → «Готово».
4. Редактор включён: снимок → «Копировать» → вставка в мессенджер → `Esc`: редактор закрыт без вопроса, файл не создан.

**Граничные случаи:**

- `Esc` сразу после открытия (изменений нет) — редактор закрывается без вопроса, ничего не сохранено.
- Пользователь нарисовал штрих, потом отменил его (`Ctrl+Z`) — изменений нет: перемещение снова доступно, `Esc` закрывает без вопроса.
- Штрих начат внутри изображения, курсор ушёл за пределы окна или холста — штрих продолжается, пока кнопка зажата, и отсекается по границе изображения.
- Окно редактора потеряло фокус во время рисования (например, всплыло окно другого приложения) — текущий штрих завершается в последней известной точке.
- В режиме «Несколько областей» пользователь рисует на пустой зоне между фрагментами — допустимо, штрих рисуется поверх заливки.
- Фрагмент перетащен так, что у изображения появились пустые полосы, — они остаются до «Склеить» и заливаются цветом REQ-002.21.
- Фрагмент перетащен влево-вверх за пределы изображения — изображение расширяется, начало координат снова (0, 0).
- 50 фрагментов (максимальный лимит REQ-002.27) — перемещение и «Склеить» работают в рамках REQ-003.N3.
- Включён указатель мыши, и он попал во фрагмент — двигается вместе с фрагментом (REQ-003.31).
- Горячая клавиша захвата при открытом редакторе — игнорируется, редактор выводится на передний план (REQ-003.13).
- Пользователь выключил флажок редактора в настройках при открытом редакторе — текущий редактор работает до закрытия, следующий снимок обрабатывается без редактора (REQ-003.4).
- Автосохранение выключено (REQ-001.35) — «Готово» только копирует в буфер и показывает уведомление без имени файла (как REQ-001 при выключенном автосохранении).
- «Копировать», затем ещё штрих, затем `Esc` — есть несохранённые изменения, система спрашивает подтверждение. В буфере остаётся версия на момент «Копировать».
- «Готово» нажато, а директория по умолчанию недоступна — REQ-001.31, изображение доступно в «Сохранить как…» из трея.
- Пункт трея «Сохранить как…» при открытом редакторе — сохраняет предыдущий последний снимок, а не открытый в редакторе (тот ещё не стал последним, REQ-003.3).
- Захват 1×1 / очень маленькая область (2×2) — редактор открывается, при масштабе «вписать» снимок показывается в 100 % по центру холста.
- Монитор, на котором открыт редактор, отключили — Windows переносит окно на другой монитор, редактирование продолжается.

## 7. Допущения и ограничения

- **Допущение:** штрихи не привязаны к фрагментам и лежат поверх всего изображения. Поэтому после первого штриха
  перемещение блокируется (REQ-003.30), а не переносит штрихи вместе с фрагментами. Пользователь подтвердил этот вариант.
- **Допущение:** состав палитры (6 цветов) и варианты толщины (2/4/8/16 px) выбраны аналитиком. Произвольный выбор цвета
  (как «Цвет заливки» REQ-002.27) в этой версии не нужен.
- **Допущение:** «Копировать» и «Сохранить как…» не закрывают редактор, чтобы пользователь мог продолжить правку.
  Закрытие — только «Готово» или «Отмена».
- **Допущение:** клавиши редактора фиксированы (`Ctrl+Enter`/`Ctrl+S`, `Ctrl+C`, `Ctrl+Shift+S`, `Esc`, `Ctrl+Z`,
  `Ctrl+Y`/`Ctrl+Shift+Z`, `Ctrl+0`, `Ctrl+1`). Настройка клавиш — кандидат на следующую версию.
- **Допущение:** открытый редактор считается незавершённым захватом для REQ-001.5. Измерения REQ-001.N1–N3 при включённом
  редакторе не применяются: вместо них — REQ-003.N1.
- **Допущение:** ограничение размера REQ-003.27 (сумма ширин × сумма высот) достаточно, чтобы разложить фрагменты в строку
  или столбец, и не даёт случайно получить огромное пустое изображение.
- **Ограничение:** прозрачность не поддерживается (CF_DIB, REQ-001 §7). Все пустоты — непрозрачный цвет заливки.
- **Влияние на существующие документы:** REQ-001 §2 («Не входит: аннотирование и редактирование снимка») частично
  снимается этим документом. REQ-002.25 (передача результата в конвейер) при включённом редакторе выполняется через
  «Готово» (REQ-003.37).
