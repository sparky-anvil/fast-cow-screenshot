# US-013: Перемещение и склейка областей в редакторе

| Поле | Значение |
|---|---|
| Статус | Draft |
| Приоритет | Should |
| Оценка | L |
| Требования | REQ-003 (3.23–3.36), REQ-002.20–22 |

## История

**Как** пользователь, выделивший несколько областей,
**я хочу** в редакторе переставить фрагменты, как мне удобно, и заново склеить их без пустот,
**чтобы** получить компактное изображение с нужной раскладкой, а не только с той, что получилась по положению на экране.

## Критерии приёмки

### AC-1: Исходная раскладка
- **Given** редактор включён; регионы A = (0,0)–(100,50), B = (500,300)–(700,400)
- **When** пользователь нажимает `Enter` на оверлее
- **Then** редактор открывается с изображением 300×150: A в (0,0), B в (100,50), пустоты — цвет заливки; выбран инструмент «Перемещение»

### AC-2: Перемещение фрагмента
- **Given** раскладка из AC-1
- **When** пользователь перетаскивает B так, что его левый верхний угол оказывается в (0,50)
- **Then** изображение 200×150: A в (0,0), B в (0,50); размер в окне обновился сразу

### AC-3: Нормализация в (0,0)
- **Given** раскладка из AC-2
- **When** пользователь тащит A влево на 30 px
- **Then** изображение 230×150; A в (0,0), B в (30,50) — начало координат всегда в (0,0)

### AC-4: Запрет наложения
- **Given** два фрагмента
- **When** пользователь перетаскивает один так, что он перекрывает другой, и отпускает кнопку
- **Then** во время перетаскивания пересечение подсвечено; после отпускания фрагмент вернулся на исходное место, показана подсказка «Области не должны пересекаться»; изменение не попало в историю

### AC-5: Касание допускается
- **Given** A шириной 100 px в (0,0)
- **When** пользователь ставит B левым краем в x = 100 на той же высоте
- **Then** фрагменты стоят вплотную, перемещение принято

### AC-6: «Склеить»
- **Given** фрагменты после перемещения стоят с пустыми полосами между ними
- **When** пользователь нажимает «Склеить»
- **Then** пустые полосы по X и по Y удалены по алгоритму REQ-002.20, взаимное расположение сохранено

### AC-7: Ограничение размера
- **Given** фрагменты 100×50 и 200×100
- **When** пользователь тащит фрагмент далеко вправо
- **Then** ширина изображения не превышает 300 px, высота — 150 px

### AC-8: Блокировка после рисования
- **Given** пользователь переключился на «Карандаш» и нарисовал штрих
- **When** он пытается выбрать «Перемещение» или нажать «Склеить»
- **Then** обе кнопки недоступны, видна подсказка «Перемещение недоступно после рисования. Отмените штрихи, чтобы двигать области»

### AC-9: Разблокировка через Undo
- **Given** состояние AC-8
- **When** пользователь отменяет штрих `Ctrl+Z`
- **Then** «Перемещение» и «Склеить» снова доступны

### AC-10: Undo перемещения
- **Given** выполнено перемещение B и «Склеить»
- **When** пользователь дважды нажимает `Ctrl+Z`
- **Then** раскладка совпадает с исходной (AC-1) пиксель в пиксель

### AC-11: Только режим «Несколько областей»
- **Given** снимок режима «Область» или «Монитор под курсором»
- **When** редактор открыт
- **Then** инструмента «Перемещение» и кнопки «Склеить» нет

## Граничные случаи

- Одна область — перемещение не меняет изображение (REQ-003.32).
- 50 фрагментов — перемещение ≥ 30 кадров/с, «Склеить» ≤ 200 мс.
- Фрагмент утащен за пределы видимой части холста — холст расширяется, есть прокрутка.
- Сдвиг стрелками (Could): 1 px, с `Shift` — 10 px; сдвиг, дающий пересечение, не выполняется.
- Указатель мыши внутри фрагмента двигается вместе с фрагментом (Could).
- Фрагменты, частично залитые `#808080` (вне мониторов, REQ-002.12), — заливка внутри фрагмента двигается вместе с ним.

## Заметки / UI

- При наведении — курсор «перемещение» и рамка фрагмента; рамки, номера, подсветка в итоговое изображение не попадают.
- Переключение инструментов — кнопками панели. **Допущение:** клавиши `V` («Перемещение») и `P` («Карандаш»).
