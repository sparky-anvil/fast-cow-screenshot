# ADR-006: Редактор снимков: окно Compose + Canvas (Skia), модель с историей в пакете `editor`, итог — рендер Java2D

| Поле | Значение |
|---|---|
| Статус | Accepted |
| Дата | 2026-11-15 |
| Автор | Tech |
| Связанные | REQ-003, US-011 – US-014, ADR-001, ADR-002, ADR-005, TDD-004 |

## Контекст

REQ-003 добавляет окно редактора, которое открывается вместо немедленной отправки снимка в буфер. В нём есть
карандаш, перемещение и склейка фрагментов режима «Несколько областей», Undo/Redo, масштаб и прокрутка. Нужно решить:

1. **UI-технологию холста и окна.** Ограничения: REQ-003.N2 (≥ 30 кадров/с при 3 × 4K, 11520 × 2160), REQ-003.N3
   (Undo/Redo и «Склеить» ≤ 200 мс), REQ-003.N6 (heap ≤ 400 МБ, без роста памяти после 50 открытий), масштаб 100 % —
   один пиксель снимка на один физический пиксель (REQ-003.9).
2. **Модель документа и истории** (REQ-003.33–37: глубина ≥ 100, отмена всех шагов даёт исходный снимок пиксель в
   пиксель).
3. **Как получить итоговое изображение** для буфера, файла и «Сохранить как…» (REQ-003.21, 42–44).
4. **Как встроить редактор в конвейер** `CaptureCoordinator` (REQ-003.2, 5, 13, 14, 41, 44).
5. **Размещение окна** на мониторе, где был курсор в момент нажатия клавиши (REQ-003.7), и подтверждение закрытия
   (REQ-003.40, 45).

## Рассмотренные варианты

1. UI:
   - **A1** — `ComposeWindow` + Compose `Canvas` (Skia, GPU). Снимок один раз переводится в `ImageBitmap`; фрагменты
     рисуются из него по прямоугольникам-источникам, штрихи — векторно, каждый кадр.
   - **A2** — Swing `JFrame` + `JPanel` (Java2D), как у оверлеев. Чтобы получить 30 кадров/с при 100 штрихах, нужен
     растровый кэш штрихов и его пересборка на каждый Undo.
2. История:
   - **B1** — команды `AddStroke(stroke)` и `ChangeLayout(before, after)` (полные списки позиций фрагментов). Состояние
     = позиции + список штрихов, пиксели исходного снимка не меняются.
   - **B2** — растровые снимки состояния на каждый шаг: 100 × 100 МБ — нарушает REQ-003.N6.
3. Итоговое изображение:
   - **C1** — чистая функция `EditorRenderer.render(snapshot)` (Java2D) на неизменяемом снимке состояния, на потоке
     `fcs-capture`.
   - **C2** — снимок экрана из Skia-поверхности холста — зависит от масштаба и видимой области.
4. Интеграция:
   - **D1** — интерфейс `ScreenshotEditor` в пакете `capture`. Координатор держит `busy` всё время, пока открыт
     редактор, и получает результат через обратные вызовы `EditorHost` (`done`, `copy`, `saveAs`, `cancel`).
   - **D2** — отдельный конвейер в UI — дублирует буфер обмена, автосохранение и уведомления.
5. Окно и подтверждение:
   - **E1** — до показа окна переместить его в рабочую область нужного монитора через `SetWindowPos` (физические
     координаты), затем `extendedState = MAXIMIZED_BOTH` (Windows разворачивает окно на том мониторе, где оно
     находится). Подтверждение — модальный `JOptionPane` с кнопками «Закрыть» / «Вернуться».
   - **E2** — подбор `GraphicsDevice` по логическим границам AWT — на смешанном DPI координаты AWT неоднозначны.

## Сравнение

| Критерий | A1 / B1 / C1 / D1 / E1 | Альтернативы |
|---|---|---|
| REQ-003.N2/N3 | Перерисовка на GPU, Undo меняет только модель (O(1)) | A2 — нужен кэш и пересборка; B2 — память |
| REQ-003.N5/36/43 | Итог детерминированно строится из исходных пикселей | C2 зависит от масштаба |
| REQ-003.N6 | Исходный снимок 1 раз в heap + 1 раз нативно в Skia | B2 — ×100 |
| Сложность | Логика — чистые классы с unit-тестами; Compose — только отрисовка и ввод | A2 — проще ввод, сложнее отрисовка |
| Зависимости | Новых нет (Skia входит в Compose Desktop) | — |

## Решение

Выбраны **A1, B1, C1, D1, E1**:

- Новый пакет `editor` (без Compose, JNA, Swing) содержит `FragmentLayout`, `Stroke`, `EditorState` (история),
  `EditorSnapshot` (неизменяемый) и `EditorRenderer` (Java2D), а также `Viewport`.
- Пакет `ui` содержит `EditorController` (логика окна без Compose, с unit-тестами), `EditorKeymap`, `EditorWindow`
  (`ComposeWindow`) и `EditorImages` (прямое преобразование `TYPE_INT_RGB` → Skia `Bitmap` BGRA без промежуточного
  `IntArray`).
- В пакете `capture` появляются `ScreenshotEditor`, `EditorHost` и `EditorRequest`. `CaptureCoordinator` открывает
  редактор вместо `finish`, если включена настройка `openInEditor`. «Готово» рендерит снимок и вызывает существующий
  `finish`.
- Если раскладка фрагментов не менялась, итог = точная копия исходного снимка (сохраняются в том числе части указателя
  мыши, выходящие за фрагмент); если менялась — заливка + фрагменты построчным `System.arraycopy`. Штрихи рисуются
  Java2D со сглаживанием, `BasicStroke(CAP_ROUND, JOIN_ROUND)`.

## Последствия

- **Положительные:** новых зависимостей нет; вся логика (раскладка, история, рендер, масштаб, клавиши, жесты)
  покрывается unit-тестами без окна; Undo/Redo мгновенны.
- **Отрицательные / риски:**
  - экранная отрисовка (Skia) и итог (Java2D) — разные растеризаторы: края сглаженных штрихов на экране и в файле могут
    отличаться на 1 px полутона; на пиксели вне штрихов это не влияет (REQ-003.N5);
  - позиция мыши в Compose Desktop приходит в логических единицах AWT × масштаб: на мониторе 200 % точность указателя —
    2 физических пикселя (точное смещение — стрелками, REQ-003.29);
  - после перемещения фрагментов части указателя мыши, нарисованные вне фрагмента, теряются (допущение TDD-004);
  - текстура Skia больше 16384 px по стороне (≥ 5 мониторов 4K в ряд) не проверялась — риск записан в TDD-004.
