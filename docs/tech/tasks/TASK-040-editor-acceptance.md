## 1. Цель

Проверить редактор целиком на собранном дистрибутиве и замерить нефункциональные требования REQ-003.N1 – N6. Код не
пишется. Результат — заполненная таблица раздела 12 в «Журнале выполнения».

## 2. Контекст

Функциональность реализована в TASK-031 – TASK-039. Логи: `%LOCALAPPDATA%\fast-cow-screenshot\logs\app.log`.
Нужные строки:
- `Editor opening <MODE> WxH` — координатор передал снимок редактору;
- `Editor shown in N ms` — окно показано (N — от нажатия клавиши для режимов 1/2 и от отпускания/подтверждения для
  режимов 3/4) — REQ-003.N1;
- `Editor done: rendered WxH in N ms` и следующая `Captured <MODE> WxH in N ms` — от нажатия «Готово» до буфера —
  REQ-003.N4.

Процесс дистрибутива — `FastCScreen.exe`; процессов два (лаунчер ~6 МБ и JVM) — для замеров брать процесс с
наибольшим `WorkingSet64`.

**Выдержки из требований (дословно):**

> **REQ-003.N1** Редактор со снимком появляется ≤ 500 мс после захвата (для режимов «Область» и «Несколько областей» — после отпускания кнопки или подтверждения) для снимка 3840×2160 и ≤ 800 мс для 3 × 4K.
>
> **REQ-003.N2** Штрих карандаша отображается с задержкой ≤ 50 мс от движения мыши, ≥ 30 кадров/с при снимке 3 × 4K и масштабе «вписать в окно».
>
> **REQ-003.N3** Перетаскивание фрагмента — ≥ 30 кадров/с при 10 фрагментах суммарно 3 × 4K. «Склеить», Undo, Redo — ≤ 200 мс.
>
> **REQ-003.N4** От «Готово» до появления изображения в буфере ≤ 500 мс для 3 × 4K и 100 штрихов.
>
> **REQ-003.N5** Пиксели, которых не касались штрихи, совпадают с исходным снимком (методика REQ-001.N5). «Готово» без изменений — 0 отличающихся пикселей относительно снимка без редактора. Перемещённый фрагмент совпадает с исходной областью пиксель в пиксель.
>
> **REQ-003.N6** Пиковый heap при открытом редакторе со снимком 3 × 4K и 100 изменениями в истории ≤ 400 МБ (REQ-001.N6). После закрытия редактора память освобождается: требования RSS из REQ-001.N6 (≤ 300 МБ в простое, без роста от числа открытий) выполняются после 50 открытий редактора.

## 7. Пошаговая реализация

### Шаг 1. Дистрибутив
- `.\gradlew.bat createDistributable` → запустить `build\compose\binaries\main\app\FastCScreen\FastCScreen.exe`.
- В настройках включить «Открывать снимок в редакторе», выключить «Включать указатель мыши в снимок».

### Шаг 2. Сценарии
- Выполнить каждый AC из таблицы раздела 12 и отметить результат (AC-критерии — дословно в US-011 – US-014; шаги
  ручной проверки TASK-038 §12 и TASK-039 §12 можно использовать как сценарии).

### Шаг 3. Замеры
- **N1:** 1 «прогревочное» открытие (`Ctrl+Shift+1` → `Esc`), затем по 5 раз: `Ctrl+Shift+1` на мониторе 4K
  (или самом большом) → `Esc`; `Ctrl+Shift+2` (весь стол) → `Esc`. Записать первое значение `Editor shown in` и
  максимум прогретых для каждого режима.
- **N2:** на снимке `Ctrl+Shift+2` в масштабе «вписать» быстро рисовать круги 5 с — линия идёт за курсором без
  заметного отставания и рывков.
- **N3:** `Ctrl+Shift+4`, 10 областей по всем мониторам → `Enter` → перетаскивать фрагмент 5 с — без рывков;
  «Склеить», `Ctrl+Z`, `Ctrl+Y` — результат появляется без заметной паузы (на глаз ≤ 0,2 с).
- **N4:** на снимке `Ctrl+Shift+2` нарисовать 100 коротких штрихов → `Ctrl+Enter`; 3 повтора; записать максимум
  `Captured … in N ms`, идущего сразу после `Editor done`.
- **N5:**
  1. Выключить редактор; открыть статичную картинку на весь монитор (например, PNG в «Фотографиях», без анимаций);
     `Ctrl+Shift+1`; переименовать новый файл в `off.png`.
  2. Включить редактор; не двигая мышь, в ту же минуту `Ctrl+Shift+1` → `Ctrl+Enter`; переименовать файл в `on.png`.
  3. `Get-FileHash off.png, on.png` — хэши равны (один и тот же кодировщик даёт одинаковые байты для одинаковых
     пикселей). Если хэши разные — повторить ещё раз (могли смениться часы на панели задач); если снова разные — CLR.
  4. Перемещённый фрагмент: `Ctrl+Shift+4` с двумя областями на статичной картинке → переместить фрагмент → «Готово»
     → в Paint на 800 % сравнить фрагмент с исходной картинкой — совпадение по пикселям.
- **N6:**
  1. Heap: открыть `Ctrl+Shift+2`, нарисовать 100 штрихов, не закрывая выполнить
     `jcmd <pid> GC.heap_info` (pid — JVM-процесс `FastCScreen`), записать `used`; затем `Ctrl+Enter` и сразу ещё раз
     `GC.heap_info`. Если `jcmd` недоступен для app-image — `.\gradlew.bat run` и тот же замер.
  2. RSS: перезапустить приложение; 50 раз `Ctrl+Shift+2` → `Esc`; через 60 с простоя записать `WorkingSet64`
     (`Get-Process FastCScreen | Sort-Object WorkingSet64 -Descending | Select-Object -First 1 WorkingSet64`);
     ещё 50 открытий → через 60 с ещё раз. Ожидание: оба ≤ 300 МБ, разница ≤ 10 %.
