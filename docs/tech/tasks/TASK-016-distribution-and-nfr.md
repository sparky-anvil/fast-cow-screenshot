## 1. Цель

Получить папку с `fast-cow-screenshot.exe` и встроенным runtime: она работает на машине без установленной Java.
На ней измерить время, память и стабильность по NFR REQ-001.

## 2. Контекст

- `build.gradle.kts` содержит `compose.desktop.application.nativeDistributions` с явным списком `modules(...)`
  (TASK-018, CLR-004: Temurin 25 без `jmods` не может включить `jdk.jlink`, поэтому `includeAllModules` не используется)
  и `jvmArgs` (`--enable-native-access=ALL-UNNAMED`, `--sun-misc-unsafe-memory-access=allow`, `-Xmx768m`).
- Задача `createDistributable` (Compose Gradle plugin) вызывает `jpackage --type app-image`. WiX для неё не нужен.
- Время в логе: `Captured <mode> WxH in N ms` (TASK-010), `Overlay shown in N ms` (TASK-013), `Saved <path> in N ms` (TASK-009).

**Выдержки из требований (дословно):**

> **REQ-001.N1** «Монитор под курсором» 3840×2160: от нажатия клавиши до появления изображения в буфере обмена ≤ 300 мс.
>
> **REQ-001.N2** «Все мониторы», 3 × 3840×2160: … ≤ 700 мс.
>
> **REQ-001.N3** «Область»: оверлей … ≤ 250 мс после нажатия клавиши.
>
> **REQ-001.N4** Файл PNG 3840×2160 полностью записан на SSD ≤ 1,5 с после захвата.
>
> **REQ-001.N6** Пиковое потребление heap при захвате 3 × 4K ≤ 400 МБ. RSS процесса в простое (в трее): ≤ 200 МБ через 60 с после запуска, до первого снимка; ≤ 300 МБ через 60 с простоя после любого числа снимков, без роста от числа снимков (разница RSS после 10 и после 110 снимков ≤ 10 %). (ред. 3, CLR-006)
>
> **REQ-001.N7** 1000 захватов подряд без ошибок. Рост heap после полного GC — не более 10 % от значения после первого захвата.

## 7. Пошаговая реализация

### Шаг 1. Собрать дистрибутив
- `.\gradlew.bat createDistributable`.
- **Результат:** есть `build\compose\binaries\main\app\fast-cow-screenshot\fast-cow-screenshot.exe` и папка `runtime`.

### Шаг 2. Проверить запуск без Java (пользователь)
- Скопировать папку `build\compose\binaries\main\app\fast-cow-screenshot` на машину или в учётную запись без Java
  (или временно убрать Java из `PATH` и `JAVA_HOME` в новом окне PowerShell) и запустить `fast-cow-screenshot.exe`.
- **Результат:** значок в трее, `Ctrl+Shift+1` работает; в `app.log` нет `WARNING: A restricted method`.

### Шаг 3. Замеры (пользователь, на эталонной конфигурации REQ-001 §4)
Выполнить по 50 раз и записать p95 (95-е значение по возрастанию из 50 — 48-е):

| NFR | Действие | Источник значения | Порог |
|---|---|---|---|
| N1 | `Ctrl+Shift+1` на мониторе 4K | `Captured MONITOR_UNDER_CURSOR … in N ms` | ≤ 300 |
| N2 | `Ctrl+Shift+2` на 3 × 4K | `Captured ALL_MONITORS … in N ms` | ≤ 700 |
| N3 | `Ctrl+Shift+3` | `Overlay shown in N ms` | ≤ 250 |
| N4 | любой захват 4K | `Saved … in N ms` | ≤ 1500 |

### Шаг 4. Память (пользователь)
- RSS в простое: Диспетчер задач → «Подробности» → `fast-cow-screenshot.exe` → «Рабочий набор (память)» через 1 мин
  после запуска и после 10 снимков и 1 мин простоя. Порог 200 МБ.
- Heap: `jcmd <pid> GC.heap_info` (из JDK 25) сразу после `Ctrl+Shift+2` на 3 × 4K. Порог 400 МБ.

### Шаг 5. Стабильность N7 (пользователь)
- 1000 снимков `Ctrl+Shift+1` (допустимо утилитой автонажатия). `jcmd <pid> GC.run` и `GC.heap_info` после 1-го и
  после 1000-го. Рост ≤ 10 %; в логе нет `ERROR`.
- В Диспетчере задач (колонка «Объекты GDI») число объектов GDI после 1000 снимков не выросло больше чем на 50.

### Шаг 6. Совместимость N8
- Шаги 2–3 на Windows 10 22H2 x64 и Windows 11 22H2+ x64.

## 8. Алгоритм и логика

p95 из 50 замеров: отсортировать по возрастанию, взять элемент с номером 48 (`ceil(0.95 × 50) = 48`).
