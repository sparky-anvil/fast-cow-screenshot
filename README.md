# FastCScreen
Приложение для создания скриншотов с параметризацией

## Работа с агентами

Разработка ведётся цепочкой из трёх агентов [Kilo](https://kilo.ai). Каждый агент работает в своей зоне и передаёт результат следующему:

```
Analyst ──► Tech ──► Dev
              ▲       │
              └─ CLR ─┘   (вопросы о поведении системы: Dev → Analyst → Tech)
```

| Агент | Роль | Что создаёт | Где | Команда |
|---|---|---|---|---|
| **Analyst** | Системный и бизнес-аналитик | Требования (REQ), user stories (US), исследования (RES), ADR | [docs/analysis/](docs/analysis/README.md) | `/analyze`, `@analyst` |
| **Tech** | Технический лид | Технические соглашения, технические дизайны (TDD), задачи (TASK), технологические ADR | [docs/tech/](docs/tech/README.md) | `/tech`, `@tech` |
| **Dev** | Разработчик | Код, тесты, запросы уточнения (CLR) | `src/`, файлы сборки | `/dev`, `@dev` |

### Analyst

Превращает идеи в проверяемые требования: формулирует функциональные и нефункциональные требования, user stories с критериями приёмки Given/When/Then и разбирает граничные случаи. Если что-то неясно, задаёт уточняющие вопросы. Код не пишет. Также отвечает на запросы уточнения (CLR) о поведении системы.

```
/analyze Добавить захват отдельного окна по горячей клавише Ctrl+Shift+4
/analyze CLR-002
```

### Tech

По документам Analyst принимает технические решения: стек, библиотеки и их версии, архитектуру, многопоточность. Спорные вопросы выносит на выбор пользователя с вариантами. Пишет технический дизайн и делит его на очень подробные, самодостаточные задачи для Dev: точные пути, сигнатуры, шаги, константы, тесты и команды проверки. Код не пишет. Также отвечает на технические CLR от Dev.

```
/tech REQ-001
/tech CLR-001
```

### Dev

Реализует одну задачу за раз строго по документации Tech: пишет код и тесты, собирает проект, выполняет проверки. Интерактивные проверки поручает пользователю. Ведёт статус и журнал задачи. Серьёзных решений сам не принимает: при неясности или противоречии оформляет запрос уточнения (CLR) к Tech, Analyst или пользователю. Коммиты делает только по просьбе пользователя.

```
/dev TASK-001
/dev
```

Без аргумента Dev берёт первую задачу со статусом `Ready`, у которой выполнены все зависимости.

### Типовой цикл

1. `/analyze <идея>` — Analyst оформляет требования в `docs/analysis/`.
2. `/tech REQ-NNN` — Tech готовит дизайн и задачи в `docs/tech/`.
3. `/dev` — Dev реализует очередную задачу и переводит её в статус `Review`.
4. Если Dev создал CLR — `/tech CLR-NNN` (или `/analyze CLR-NNN`), затем снова `/dev TASK-NNN`.
5. Пользователь проверяет результат и переводит задачу в `Done`.

Конфигурация агентов, команд и шаблонов — в [.kilo/](.kilo/).
